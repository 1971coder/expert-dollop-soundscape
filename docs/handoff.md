## Open Issues

- **WP02 should-fix #2 — Repositories are `@MainActor`, contradicting `architecture.md` §5.** *(Integration review 2026-05-29.)* `architecture.md` §5 says "Persistence: Background actor; never on audio thread"; the WP02 repos are main-actor and use `container.mainContext` sync. `data-model.md` *As-built notes* documents the deviation but `architecture.md` itself wasn't updated to match. **Fix:** either move repos to `@ModelActor`, or amend `architecture.md` §5 with the main-actor-on-MVP, background-actor-on-WP-N decision and a forward link to the WP that flips it.
- **WP02 should-fix #3 — Five of seven repository methods lack an error-path test.** *(Integration review 2026-05-29.)* Acceptance criterion: *"All Persistence repository methods have happy-path + at least one error-path test."* Covered: `SessionRepository.finalize`, `PresetRepository.delete` (both `.notFound`). Uncovered: `SessionRepository.create`, `.list`, `.purgeAll`; `PresetRepository.list`, `.save`. **Fix:** add tests that simulate SwiftData throw paths (closed container, fetch-with-invalid-predicate), or amend the WP brief to scope the criterion to methods with an explicit error type.
- **WP02 should-fix #4 — Intensity slider only modulates `masterGain`.** *(Integration review 2026-05-29.)* Acceptance criterion: *"more presence at higher intensity, smoother fades at lower"* implies multi-axis modulation. `SessionStateManager.applyIntensity(_:)` sends one `ParameterDelta` (`.masterGain`). **Fix:** extend `applyIntensity` to also affect `.filterCutoff` (lower intensity → darker) and `.pulseRate` / `.pulseDepth` (lower intensity → slower / softer breathing).
- **WP02 should-fix #5 — App-level smoke test missing.** *(Integration review 2026-05-29.)* `testing-strategy.md` mandates an `App/` smoke test that "the app launches and constructs the engine." Currently the only launch coverage is `CriticalPathTests` (XCUI, ~13 s). A `@MainActor func testAppDependenciesConstructsAllSubsystems()` unit test would catch DI wiring breaks for a fraction of the cost.
- **`scripts/format.sh` does not fall back to `xcrun swift-format`.** swift-format ships with Xcode at `xcrun swift-format` but the script only looks at `$PATH`. Out of WP02's allow-list (`scripts/format.sh` is not in *Shared Files Allowed To Change*) — file a tiny follow-up WP or bundle into the next scripts/* touch. Carried from WP01.
- **iOS Simulator must be pre-booted before `./scripts/test.sh`.** Running tests against a cold simulator triggers `FBSOpenApplicationErrorDomain Code=6: Application failed preflight checks (Busy)`. Workaround: `xcrun simctl boot "iPhone 17 Pro Max"` then run the test script. Cause appears to be xcodebuild's auto-boot racing with the bundle install. Worth folding into `_xcode-destination.sh` (an explicit warm-boot step) in a future scripts WP.
- **Focus mode also continues playing when backgrounded.** The MVP entitlement is global (`UIBackgroundModes = audio`) and the WP did not add a scene-phase pause for non-Sleep modes. Users may find this surprising. Tracked in `decisions.md` 2026-05-29 ("Background audio entitlement"); revisit if a complaint or product-design pass calls for per-mode pause logic.

## Assumptions In Play

- **No first-party server.** No backend in MVP; cloud LLM calls (Phase 4) are vendor-direct.
- **One designated parameter drainer.** `DroneSynth` drains the ring buffer each render block; `NoiseGenerator` and `PadSynth` read from the shared `EngineParameters`. Non-drainer nodes may see params one block stale (≤ ~6 ms) — acceptable for ambient parameters but worth re-validating when WP03 wires AdaptiveController-driven parameter changes at higher rate.
- **`HistoryView`'s `@Query` reads from the SwiftUI environment's `ModelContainer`.** `AuralFlowApp` injects it via `.modelContainer(dependencies.modelContainer)`. Sheets-as-history work because SwiftUI carries the environment through `.sheet`. If a future WP moves history into a different presentation pattern (NavigationStack push, e.g.) the environment plumbing must follow.
- **`AdaptiveProfileRepository` is protocol-only in WP02.** WP03 implements `current` / `upsert` / `delete` and ships the `@Model AdaptiveProfileRecord`. The placeholder value-type `AdaptiveProfile` in `Persistence/Models/` carries only `id` and `lastUpdated` — fleshed out in WP03 per `data-model.md` §4.

## Technical Debt To Revisit

- **Naming drift:** repo dir and Xcode target are `Soundscape`; product / Swift entry point are `AuralFlow`. The Xcode target rename remains its own deferred WP (see `decisions.md` 2026-05-17).
- **`README.md` at the repo root** is still the scaffold's README, not AuralFlow's. Low priority.
- **SwiftLint custom rules under `Audio/`** are still minimal (one rule: no `print()` under `Audio/`). Tighten in WP03 — extend to flag `os_log` and dispatch-async on the render path.
- **`ParameterRingBuffer` ordering — interim solution still in place.** Commit `604d9e8` added `OSMemoryBarrier()` release/acquire fences around head/tail publication. The barriers are the interim mechanism; long-term, swap to `Synchronization.Atomic<UInt32>` once the deployment target reaches iOS 18+. Track alongside the deployment-target bump WP.
- **`AudioEngine.handleRouteChange(_:)` has no automated coverage.** The route-change-failure → `EngineState.failed` path *is* now testable via `FakeAudioEngine.simulateRouteChangeFailure()` (covered in `SessionStateManagerTests`), but the real `AudioEngine` route-change branch — `engine.pause()` / `engine.prepare()` / `engine.start()` recovery — still has no automated coverage. Hard to drive without an integration test on a real device; defer to a WP that flexes real route logic (e.g. binaural-gated by headphone detection).
- **`AVAudioFormat(commonFormat:sampleRate:channels:interleaved:)!` duplication has grown.** Now in `AudioEngine.swift`, `AudioEngineSmokeTests.swift`, `DroneSynthTests.swift`, `NoiseGeneratorTests.swift`, **and** `PadSynthTests.swift`. Factor into a `SoundscapeTests/AudioTests/TestSupport/Format.swift` helper when the next audio test file lands.
- **`AudioEngine` is `nonisolated final class` + lock, not an actor.** `decisions.md` 2026-05-29 records the choice and the constraint that forced it (Apple's AVFoundation Sendable annotations). Revisit when Apple ships AVFoundation Sendable conformances, or if the SWIFT_DEFAULT_ACTOR_ISOLATION default is dropped — at that point the actor route becomes cleaner.
- **`xcuserdata/` under `Soundscape.xcodeproj/`** has not been audited for accidentally-committed user state. Low priority, but worth a sweep in the same WP that does the README rewrite.
- **`factoryEpoch` duplicated** *(Integration review 2026-05-29.)* The literal `Date(timeIntervalSince1970: 1_748_563_200)` appears file-private in both `Soundscape/Modes/Presets/FocusPresets.swift:30` and `Soundscape/Modes/Presets/SleepPresets.swift:30`. Tiny dup; lift into a `Modes/Presets/PresetEpoch.swift` when WP03 ships RelaxPresets / WalkPresets (the WP that adds the third copy is the right moment).
- **`api-contract.md` §1 doesn't enumerate `AudioEngineError` cases** *(Integration review 2026-05-29.)* WP02 added the `routeChangeFailures: AsyncStream<AudioEngineError>` requirement to `AudioEngineControl` but didn't document the three `AudioEngineError` cases (`sessionConfiguration`, `engineStart`, `routeChangeRecoveryFailed`). WP03's `AdaptiveController` will be the next consumer; add the case list in the next docs touch on `api-contract.md`.
- **`Soundscape/Sessions/` missing from `project-structure.md` layout diagram** *(Integration review 2026-05-29.)* WP02 introduced a new top-level module under `Soundscape/` but the layout doc still lists only `App/`, `Audio/`, `Adaptive/`, `Modes/`, `Persistence/`, `Views/`, `Resources/`. Add a `Sessions/` entry (with `SessionStateManager.swift`) in the next WP that touches `project-structure.md`.
- **`testRouteChangeFailureTransitionsToFailed` waits with `Task.sleep(50ms)`** *(Integration review 2026-05-29.)* `SessionStateManagerTests` swallows a 50 ms wait to let the `AsyncStream` observation Task propagate. Flake-prone under CI load. Replace with a continuation-signal pattern when the test file is next touched.
- **SwiftLint not enforced locally** *(Integration review 2026-05-29.)* `./scripts/check.sh` only runs `swiftlint --strict` when the binary is on `$PATH`. It isn't on this machine, so `force_unwrapping` violations (e.g. the `UUID(uuidString: "...")!` literals in `FocusPresets.swift:7` and `SleepPresets.swift:7`) pass the local check silently. CI should require SwiftLint; until then assume lint coverage is partial.
- **`JSONEncoder` / `JSONDecoder` defaults baked into `ModePresetRecord.from(_:encoder:)` and `toDomain(decoder:)`** *(Integration review 2026-05-29.)* The defaults are redundant because `SwiftDataPresetRepository` always passes its held instances. The defaults invite future callers to instantiate fresh encoders per call. Drop them when `Persistence/Models/ModePreset+Model.swift` is next touched.
- **Logger error interpolations use `privacy: .public` in `AudioEngine`** *(QA review 2026-05-29; partially closed in follow-up bundle.)* `SessionStateManager` was switched to `privacy: .private` in the WP02 follow-up bundle. `AudioEngine` logs constant strings only (no interpolated error descriptions) so its current calls are PII-safe by construction — but future code on the audio path should default to `privacy: .private` for system error descriptions and reserve `.public` for string constants the implementer wrote. Pattern guidance, not an active bug.
- **`AVAudioSession.interruptionNotification` not handled** *(QA review 2026-05-29.)* Incoming calls / alarms during a Sleep session silently silence the engine because WP02 only observes `routeChangeNotification`. Surface as a "Sleep robustness" gap — most relevant for the overnight Sleep use case the background-audio entitlement targets. Add a `pause-on-.began` / `restart-on-.ended` handler when WP03 or a Sleep-polish WP touches `AudioEngine`.
- **`HistoryView`'s `@Query` has no `fetchLimit`** *(QA review 2026-05-29.)* Acceptable at MVP scale; once a daily user accumulates hundreds of rows the unbounded fetch becomes a perceptible delay. Add `fetchLimit` (e.g. 200) and a paging affordance when a perf pass calls for it.
- **`AppDependencies` `fatalError`s on `ModelContainer` init failure** *(QA review 2026-05-29.)* `Soundscape/App/AuralFlowApp.swift:33` crashes the app on a corrupt store. A graceful fallback to in-memory + a banner would let users at least run the current session. Lift to a dedicated stability WP if it ever bites a user.
- **`architecture.md` §2.1 diverges from the WP02 `PulseModulator` / `FilterController` impl** *(Architecture review 2026-05-29.)* The doc describes both as graph-level components (bus-level LFO modulating mixer channels; per-bus LP/HP); the impl ships both as state structs embedded inside each source node's render block. Either amend the doc to describe the embedded-state pattern, or refactor the impl to match. Pair with a decisions.md entry if amending the doc.
- **`@Query` in `HistoryView` bypasses `SessionRepository.list`** *(Architecture review 2026-05-29.)* `architecture.md` §1 says reads go through controllers; `HistoryView.swift:7` reads directly via SwiftData's `@Query`. Couples the view to the storage technology. Either record the "reads-from-views via `@Query` is the SwiftUI-blessed exception" decision in `decisions.md` and amend `architecture.md` to allow it, or rework `HistoryView` to fetch via the repository. The decision deserves to be written down — right now the deviation is unmarked.
- **`SessionStateManager.preset(for:)` hardcodes factory presets, ignoring `PresetRepository`** *(Architecture review 2026-05-29.)* Any user-saved preset variation is invisible to session-start. Fine for MVP (no user presets); becomes a silent gap the moment user-editable presets ship. Introduce a `PresetProvider` seam (or call `PresetRepository.list(for:)` directly) in the WP that ships user-editable presets.
- **5-site parameter-extension chain** *(Architecture review 2026-05-29.)* Adding one parameter requires synchronised edits in `ParameterId`, `EngineParameters` (field + apply switch + applyAll), `ParameterSnapshot`, and every factory preset (`FocusPresets`, `SleepPresets`). Type system enforces none of them. Acceptable at 10 parameters; revisit at 15–20 (KeyPath-indexed apply, codegen, or a dictionary-based snapshot). Add a "if you add a parameter, update all five sites" comment in `ParameterId.swift` as the lightweight near-term mitigation.
- **Single-implementation repository protocols carry uncertain weight** *(Architecture review 2026-05-29.)* `SessionRepository`, `PresetRepository`, `AdaptiveProfileRepository` exist as protocols for (a) a SwiftData→SQLite swap option and (b) testability. Reason (b) is moot — tests use the real impl with in-memory container, not a fake. Reason (a) is conditional. Decide whether to keep (forward-looking) or drop (concrete classes); record in `decisions.md` either way to stop the question recurring.
- **Designated-drainer convention isn't type-enforced** *(Architecture review 2026-05-29.)* `decisions.md` 2026-05-29 records `DroneSynth` as the sole `ParameterRingBuffer` drainer, but nothing in the type system enforces it. Two failure modes: a refactor of `DroneSynth.render` could drop the drain loop silently, or a future mode without `DroneSynth` could leave the buffer un-drained. Add a unit test that asserts drain happens, or introduce a `Drainer` protocol attached to one node, when the graph next grows.
- **`SessionStateManager` swelling risk** *(Architecture review 2026-05-29.)* Currently ~120 lines, 8 surface members. As the should-fix items from integration / QA reviews land (failure-path cleanup, multi-axis intensity, countdown, possibly a `PresetProvider`), it'll cross 250 lines. Watch for internal decomposition opportunities (e.g. a separate `EngineFailureObserver` value type).
- **`FilterController.swift` has a confusing name vs content** *(Architecture review 2026-05-29.)* The file holds `StateVariableFilter` (the actual filter struct) and a namespace enum `FilterController` (parameter-mapping helpers, doesn't control anything). Rename `FilterController` → `FilterParameters` (or merge the helpers as static members of `StateVariableFilter`) on the next touch of the file.
- **`PulseModulator` and `FilterController` live under `Audio/Nodes/` but are not `AVAudioNode`s** *(Architecture review 2026-05-29.)* The folder name implies graph node; the content is shared state. A `Audio/DSP/` or `Audio/Helpers/` sub-folder would be more honest. Cosmetic at this scale; revisit when binaural / future DSP utilities land.
- **`AppDependencies.init` runs a fire-and-forget preset seed Task** *(Architecture review 2026-05-29.)* Side effects from a constructor are invisible to readers checking the type signature. Lift to an explicit `func bootstrap() async` (called from `AuralFlowApp` on appear), or annotate with a one-line `// also kicks off factory-preset seeding` comment.
